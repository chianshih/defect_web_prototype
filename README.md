# 施工缺失管理網頁｜本機可試用原型

這是可在自己的 Windows / Mac 電腦上啟動的**本機網頁原型**，不是已上線的公開網站，也不是 ChatGPT 對話頁面。

## 已建立的功能

- 初次啟動匯入 2026/11/04 機電聯合巡檢 **32 筆缺失、32 張照片**；不使用更早的 10/31 資料。
- 網頁可用手機尺寸操作，瀏覽原始缺失照片與改善後照片，搜尋及篩選狀態。
- 上傳 JPG / PNG / WEBP 照片（每批最多 20 張、單張最多 12 MB）。
- 設定 API 金鑰後，伺服器使用 OpenAI 視覺模型讀取白板，判斷「新缺失」／「改善後」，提取白板編號、日期、樓層、缺失內容等。
- 白板**明確包含「改善後」字樣**，且缺失編號在清冊中**唯一存在**、辨識信心足夠，才自動把照片歸回原缺失，狀態改成「已改善」。此狀態**不等於複驗合格**。
- 看不清楚或編號重複的照片進入「人工確認」區；人工確認也可新增不同廠商的獨立缺失。
- 改善後照片不會覆蓋原始照片，歷次改善回覆都保留。
- 由「匯出 Excel 清冊」下載含原始及改善照片的 `.xlsx` 檔案。

## Windows 操作（最簡單）

1. 電腦先安裝 [Python](https://www.python.org/downloads/) **3.10 或以上**，安裝時勾選 Add Python to PATH。
2. 解壓縮本 ZIP 到電腦資料夾。
3. 雙擊 `start_windows.bat`，首次會安裝必要套件並開啟瀏覽器；若瀏覽器沒有自動開啟，手動輸入 http://127.0.0.1:5000 。
4. **未設定 API Key 時**，原本 32 筆仍能瀏覽、匯出 Excel；新上傳照片會放入「人工確認」，不會假裝執行 AI 判讀。
5. 如要自動判讀：把 `.env.example` 複製成 `.env`，用記事本打開 `.env`，將 `OPENAI_API_KEY=` 後面填入自己的 OpenAI API 金鑰，再重新啟動網頁。**請不要把 .env 分享給其他人，也不要把金鑰寫在網頁 HTML 裡。**

API 金鑰由 [OpenAI API 平台](https://platform.openai.com/api-keys) 建立。**API 使用費與 ChatGPT 訂閱分開計費。** 模型名稱可於 `.env` 的 `OPENAI_MODEL` 調整，預設 `gpt-4.1-mini`。

Mac / Linux：執行 `bash start_mac_linux.sh`，瀏覽 http://127.0.0.1:5000 。

## 讓同辦公室的人一起使用（區域網路）

預設只有本機能開。要讓同一個辦公室網路的手機／電腦連線：

1. 在 `.env` 加入 `HOST=0.0.0.0`（`.env.example` 有範例），重新啟動。
2. 啟動時黑色視窗會列出可分享的網址（例如 `http://192.168.1.23:5000`），網頁上方也有「分享網址」與複製按鈕。
3. Windows 第一次會跳出防火牆詢問，請只勾選「私人網路」並允許；不要勾「公用網路」。
4. 電腦的 IP 可能會變。建議請公司資訊人員為這台電腦設定 **DHCP 保留（固定 IP）**，或建立**內部 DNS 名稱**，大家就能長期使用同一個網址。
5. 這台電腦必須開機且程式保持執行，別人才連得上。

## 登入與操作紀錄

- 開啟網頁會先到登入頁：**從選單選自己的名字**即可（不用密碼），系統記住 30 天。右上角顯示「目前使用者」，可按「切換使用者」換人。
- 第一次使用（名單是空的）時，由第一個人直接輸入名字建立第一位使用者；之後新同事可在登入頁選「名單中沒有我」自行加入（`.env` 設 `ALLOW_SELF_REGISTER=0` 可關閉），或由管理員在「後台管理 → 使用者名單」新增。名字不能刪除（歷史紀錄要保留），不再使用請「停用」。
- 缺失卡片會顯示「上傳者」；清冊可篩選「只看我上傳的」或指定某人；匯出的 Excel 有「上傳者」欄；後台的操作紀錄會列出時間、操作者、IP、動作。
- **管理員**：在 `.env` 設定 `ADMIN_PASSWORD=自訂密碼` 並重啟；登入時勾選「管理員」並輸入密碼，才能使用「後台管理」。沒有設定時管理員功能停用，其他功能照常可用。
- **限制（請務必了解）**：因為選名字不需密碼，**任何人都能選別人的名字**。這個登入是為了「留下紀錄、方便追溯」，**不是資安防護**；系統同時記錄連線 IP，可輔助判斷。登入簽章金鑰存在 `data/secret_key`（請勿分享、不要上傳）。

## 標準白板方式（建議）

**開立缺失照片：**

    日期：115/11/04
    缺失編號：33
    樓層：6F
    缺失內容：風管吊架未施作
    權責廠商：○○公司

**改善照片：**

    改善後
    缺失編號：MEP-20261104-033  （或「缺失33」，但跨日期若同號會要求確認）
    改善日期：115/11/05
    改善內容：已補作風管吊架

拍攝時請讓**白板文字與改善位置同框**；大字清楚寫「改善後」和**完整缺失編號**，可以降低誤配風險。如果照片只寫「缺失 33」且另一巡檢日也有同號，系統不會任意選一筆。

## 系統如何防止配錯照片

1. 無法確認白板「改善後」標記 → 待確認。
2. 無法辨識缺失編號 → 待確認。
3. 缺失編號不存在或同號有多筆 → 待確認，不自動新增不存在的改善紀錄。
4. AI 辨識信心低 → 待確認。
5. 新缺失如果已有同日期、同編號 → 待確認，避免重複建檔。
6. 新缺失如由人工確認為不同廠商，可建立獨立系統編號（尾碼 `-2` 等），不會覆蓋前一筆；未來改善回覆遇到同號會要求選擇實際對應的項次。
7. 「已改善」代表已收改善照片；僅現場複驗後手動核定「已結案」。

## 檔案儲存與備份

首次執行會在 `data/` 建立 SQLite 資料庫與原始照片資料夾。**請定期備份整個 `data/` 資料夾**，否則換電腦或刪檔就會失去後續新增的缺失及改善回覆。照片未經美化或覆寫。

## 重要限制

- 目前僅適用**單台電腦、本機測試**；網頁只綁定 `127.0.0.1`，**尚未部署為可讓多位廠商從網際網路使用的網站**。
- **需要額外設定 OpenAI API Key** 才能真正自動判讀，沒有金鑰只會進人工確認。
- 需要對外提供廠商上傳時，必須先做好登入驗證、角色權限、HTTPS、上傳限制、惡意檔案處理、稽核紀錄、異地備份和雲端儲存；此原型尚未實作上述上線保護，**請勿直接暴露到公網**。
- AI 看不懂模糊白板的可能性仍存在；缺失責任歸屬與工程複驗必須由現場人員確認。
- 本原型**未在你的電腦上實際連接 API 金鑰進行真實識別**；已設計 API 串接與人工確認機制，請以自己的金鑰測試後再導入正式流程。
